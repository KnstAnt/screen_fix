# Elevated capture specification addendum

This addendum defines the ELC-1–6 exception for an approved elevated foreground. The [M1 specification addendum](SCREEN_FIX_M1_SPEC_ADDENDUM.md) applies the exception to INP-13, Start preflight and gate 3 of the [Windows technical specification](<Intercall Recorder technical spec v1 Windows.pdf>). The [M1 architecture](SCREEN_FIX_M1_ARCHITECTURE_ADDENDUM.md) defines ownership, and the [M1 algorithms](SCREEN_FIX_M1_ALGORITHMS_ADDENDUM.md) govern the shared capture and publication paths.

## 1. Requirements amendment

- ELC-1. Capture a positively identified elevated instance of an approved executable on the Recorder's unlocked interactive desktop. Use the standard source when the Recorder already has eligible access. Use the independently elevated, demand-started collector when additional access is required and the protected token pair is supported. Screen Fix UI, controller, WGC, encoding, stills, packaging and diagnostic writers run in the Recorder under its launch token. Standard recording needs no UAC prompt. Recorder controls and foreground gating retain their M1 scope. Recorder windows can appear in captured pixels. Full own-window image exclusion remains M3.
- ELC-2. Support the same interactive user and logon session, including the linked UAC split-token case, in the same Windows session on the normal interactive desktop. Cross-user administrator credentials, remote pipe clients, other sessions/desktops, protected targets, SYSTEM targets and targets above the selected source's integrity are outside this release. The component is an application with a single capture contract and finite lifetime. It has no UIAccess flag, service, injection or general-purpose privileged operations.
- ELC-3. Replace the unconditional INP-13 preflight rejection for this scope. On the standard source, use the existing admission and publication rules. When a separate collector is required, keep admission closed until the collector is authenticated, the live foreground is independently approved in both processes, required producers are ready and the armed held-state probe has reached a typed terminal outcome. Frame, input and context publication for the collector-backed visit stays closed through fresh resynchronization after the actual Start or Resume boundary; the ordinary timing and Start semantics remain in force. Unknown identity or access is a closed gate. The secure desktop, lock, sleep and the UAC transition remain uncaptured. The high-side gate applies before data crosses IPC and the existing core consent, privacy and publication gates apply before data enters output.
- ELC-4. Preserve the full M1 capture path. Retain raw and low-level input evidence, both hook-health paths and provenance, pen and supported HID evidence, native foreground/focus/geometry, UIA focus and point reads, password and text gates, approved commit/IME observations, resync, and current still/save decisions. Apply existing rules for ambiguity, loss, unavailability and omissions; permission changes do not justify reconstructing evidence.
- ELC-5. Declined, timed-out, unsupported or unverified elevation before admission ends startup without an admitted start. After admission, an elevation or privileged-source failure closes at the earliest safe known cutoff, finalizes the provable prefix under the existing failure flow and reports the failure. There is no automatic relaunch or privileged fallback. The user may start a new attempt; an ordinary attempt with no elevation demand follows existing M1 failure behavior.
- ELC-6. The collector must stop target-facing work on admission revocation, lost foreground/identity proof, desktop/session failure, transport/lease loss or parent death. Forced termination must be independent of UIA providers, native producer joins and the Recorder process's cleanup. Neither a delayed start result nor a delayed reply can extend an authorization.

### Inherited administrator rights

Declare the Recorder asInvoker with UIAccess disabled. Windows can give a normal Recorder launch from the built-in Administrator an already elevated token. The Recorder makes no elevation request for itself. This launch can have a default token without a linked token. Rejecting all elevated Recorder tokens blocks this sign-in even when the approved target is already accessible. Launch the standard helper with the Recorder’s existing token through the restricted inherited channel and parent-lifetime job. Both locally accessible standard and elevated foregrounds use standard readiness, source timing, foreground and privacy checks.

For inherited elevated access, the target must be unprotected, have integrity at or below the Recorder’s actual integrity, and share the interactive user and nonzero Windows session. Exclude SYSTEM. Require matching authentication LUID and logon SID or a proven reciprocal limited-medium/full-high split-token relationship. An ordinary same-sign-in match does not require querying for a linked token. An incompatible, cross-sign-in or uncertain foreground closes admission or is suppressed under the existing rules. The inherited high path cannot request a separate collector. It does not require the protected signed installation to use the standard source. Protected attachment has its own medium-to-high token proof and deployment requirements.

## 2. Process boundary and trusted installation

Use two small Windows executable entry points. The ordinary input helper retains its `asInvoker` manifest, inherited anonymous channel and job. The separately installed `screen-fix-elevated-capture.exe` has `requireAdministrator`, `uiAccess=false`, and no service registration, auto-start, shell/file association or COM server registration. Its only entry mode is one Recorder-initiated attachment. Both link the same native collection code. The high executable additionally links the narrowly extracted platform observation code. It links no WGC/GPU/video, attempt layout, filesystem output, journal, UI or exporter. It does not write recording/log files, launch processes, enable SeDebugPrivilege, impersonate the peer, send arbitrary messages, or read target files or memory. Platform calls include only the existing typed native input, UIA, IME and context operations and the local identity/lifecycle primitives described here.

Provide a machine-wide signed Windows Installer package for the matching Recorder, ordinary input helper and elevated collector. Installer ownership creates and maintains a protected product directory under the 64-bit Windows Program Files known folder. Only SYSTEM, Administrators and the Windows servicing identity may own or modify the deployed images, their loadable dependencies and protected product directory. Use the same reviewed policy for upgrade and removal. Install one compatible set, publish release hashes, use the protected directory as the working directory, and reject incomplete or mixed release installs. Verify the matching release and all three image roles with the expected publisher public key pinned in the signed binaries, Windows Authenticode verification and an immutable common release ID embedded in the signed resources. Trust-chain success alone is insufficient. Supply the publisher public key pin and release ID as required external release-build inputs, validate their canonical lengths/encoding, and embed them with the appropriate role in all three images before external Authenticode signing. An absent or invalid pin prevents an elevation-enabled release build. No private signing key, fabricated certificate, permissive default or bypass belongs in the source. The release source supplies the collector executable, Windows Installer authoring and product-side trust verification. Official Authenticode signing and release publication use external release infrastructure. Elevation-enabled builds require valid embedded trust inputs. Portable and unsigned builds retain ordinary capture and report a deployment-required outcome when the separate collector is required.

Before invoking UAC, the launcher in the eligible medium-integrity Recorder resolves the Program Files known folder through Windows and uses one absolute fixed product path. It verifies the Recorder's own installed identity as well as the collector's. Open and inspect the volume, applicable ancestors, product directory and the three matching signed role-bound images by handle, including the standard helper. Require the local NTFS Windows installation volume, reject reparse traversal, verify final handle paths and file IDs, and reject unexpected owners, NULL DACLs, access-granting ACE forms the verifier cannot safely interpret and write/replace/ACL grants to untrusted principals. Check delete-child rights on parents as well as delete/write/rename/owner/ACL rights on children; parent rights that only allow creation of unrelated names do not imply replacement of an existing pinned entry. Hold non-write/non-delete sharing guards on the protected installed paths and image handles through launch and authentication. The collector verifies its own protected image and the Recorder peer's protected image and signed release before admission. The peer's running process image must resolve to the pinned Recorder file, with the authenticated process still alive. Trusted administrators and OS servicing can change installed binaries and are in the trusted computing base.

Launch the absolute verified executable with `ShellExecuteExW`, verb `runas`, a fixed protected working directory, `SEE_MASK_NOCLOSEPROCESS` and `SEE_MASK_NOASYNC`. Retain and check the returned process handle. Missing handle, unreadable identity, signing failure, image mismatch or incompatible release cannot turn into an alternate launch. Arguments consist only of the bootstrap format version, parent PID/creation time and a fixed-length random rendezvous ID in a strict character alphabet. No environment expansion, command interpreter, caller-selected executable, inherited mapping, handle values, target path CLI or output path enters the elevated launch. Bind application imports to the protected application directory or Windows system components. Restrict dynamic DLL search to the system and protected application directories at earliest startup, use the Windows UIA client without app-supplied proxy loading, and exclude app-supplied DLL/COM registration, plugins and user-writable dependency discovery. Review both startup imports and later loads. A portable or unsigned installation still uses the standard source when eligible and gets a deployment-required outcome when the collector is required.

## 3. Authentication, bounded transport and lifetime

### 3.1 Connection

Create one local Recorder-owned bootstrap pipe before dispatching the shell. The fixed bootstrap CLI identifies it using an OS-random 128-bit rendezvous ID. On the bootstrap pipe's server handle the Recorder obtains the actual client PID with `GetNamedPipeClientProcessId`. Require equality with the process ID of the live original handle returned by this launch's `runas` before sending any secret. Reject or close an unverified connection without protocol data. The child needs no trust in the bootstrap server: this lane performs one fixed-size receive with a deadline and carries no requests, configuration or capture data.

After authenticating the boot client, the Recorder sends a separate CNG-generated 256-bit binding secret, attempt/session binding and connection ID over that accepted bootstrap instance. They never enter arguments, environment, product logs or persisted metadata. The high process creates exactly three high-owned local named pipe instances for control, input and context, using names derived from the binding secret and role under a pipe-name HMAC domain. Each such pipe authenticates its actual medium client on the server side with `GetNamedPipeClientProcessId`. The high process independently opens the observed parent for limited query and synchronize and checks expected PID/creation time, pinned image, signed release and live token pair. It retains the authenticated process handle as the parent witness and rejects a signaled handle. All three peers must be the same still-live parent. No client-side pipe PID API assumption is required.

Compare the token user SID, interactive Windows session ID, elevation, integrity and the expected medium/elevated token pair. Use token authentication/logon identity, including the actual linked token's logon identity, rather than requiring identical authentication LUIDs: the two UAC split tokens can denote two linked logon sessions. Require the high token and the live medium parent to form the established linked pair for the same user and Windows session. A new credential logon, even with matching account name, is not equivalent. The high token must be elevated high and must have a non-SYSTEM user. The installed image basename, a claimed PID, DACL and possession of the rendezvous ID do not satisfy either process check.

Each high-owned lane proves possession of the bootstrap secret via HMAC-SHA-256 on the exact live connection, only after the high side has authenticated that lane's actual Recorder PID. Use a role-specific proof domain distinct from name derivation, protocol version, attempt/session IDs, connection ID and a fresh CNG challenge generated by the medium lane client. Compare the fixed-size proof in constant time. Core sends no configuration, lease, target or capture command on any lane until all three have passed. Broken/reconnected pipes require a new launch and are failures for this attempt. Erase both copies of the secret, its derived-name and challenge buffers once all bindings complete, or on cancellation, startup failure or deadline. Closing bootstrap after its bounded transfer is normal. The boot, challenges and connect operations share the readiness deadline; do not retry one while indefinitely holding other lanes open.

Use first-instance and remote-client rejection flags, message mode, non-inheritable overlapped handles and maximum one instance per name. Every pipe has a protected explicit DACL. Bootstrap admits the same account's data access and required system/server rights. Elevated lane objects have an explicit medium mandatory label with NoWriteUp, an Administrators owner, full SYSTEM/Administrators server rights, and narrowly scoped client-mask ACEs for the medium user SID. Open duplex clients with `FILE_READ_DATA | FILE_WRITE_DATA | SYNCHRONIZE`. Use duplex for all three elevated lanes so each challenge runs on its own handle. The input decoder rejects inbound messages after binding. Leave clients in their documented default byte-read mode. The server stays in message-read mode. Each frame is one complete bounded overlapped write. A byte-mode receiver accumulates exactly the fixed header, validates its type and declared cap, then reads exactly the declared payload. EOF or truncation mid-frame is terminal. Unexpected remaining bytes fail the next header/sequence check; only a wholly valid next frame in the current state can be accepted. A message-mode receiver verifies one complete frame and its exact extent, treating unexpected `ERROR_MORE_DATA` as an oversize fault. Bootstrap has one fixed-size record. Bound completion and release overlapped buffers only after cancellation completes. Do not grant the medium client create-instance, delete, write-DACL or write-owner access, or generic write (its append right aliases create-instance). Supply the medium mandatory label in the creation descriptor, then read back the applied ACL/label through the server handle before accepting a client. Fail closed on failed creation, readback or mismatch. Use identification-only SQOS on clients and perform no impersonation. Use the fixed local namespace and exact role suffixes. Invalid endpoints, peer PID or challenge return a bounded failure. No authorization depends on pipe names remaining secret.

Without capture registration, the peers bind version, role, release ID, QPC frequency and expected attempt/session IDs. The child validates IDs, version, in-flight state and QPC frequency before accepting a single immutable configuration. It never starts native producers merely because it was elevated. Control records carry the connection ID, attempt/session and a checked direction-specific sequence. Evidence carries the connection/session, source generation and a checked position in its channel. Exact equality applies to opaque IDs and process-creation values. Session IDs, paths, rects and strings retain the existing field-level bounds. No mutable configuration crossload or renegotiation is supported.

The DACL scopes pipe access to the interactive account and required system principals. The kernel's peer process identity and the launch/process bindings reject a different local process under that same account. A same-user process may deny availability, and code already executing inside, debugging or controlling the trusted Recorder in a protected attachment can observe evidence already delivered to that Recorder and exercise its narrow capability during a user-authorized session. Windows does not isolate that Recorder from its own user. UAC consents to a particular installed image; protected installation, live peer proof, read-only scoped commands, actual target approval and finite lifetime constrain what that image can do. No privileged target evidence is sent to unauthenticated clients.

### 3.2 Wire and queue rules

Use a separate versioned elevated envelope in `protocol/src/ipc/elevated.rs`. Use fixed header fields (magic, version, role, type, direction, payload length, sequence and connection ID) and schema-checked payloads. Decode into specific bounded Rust values, using checked length/count/time conversion before allocation or indexing. Reject wrong-direction or out-of-state messages, trailing bytes, invalid enum values, duplicate setup, unknown versions, bad sequence, unbounded text and nonzero reserved fields. No handles, pointers, JSON rows, native structs, serialized COM, output paths or generic method/property selectors cross this wire. Platform-independent opaque window IDs and process tuples are evidence only, never instructions to perform a Win32 operation on an arbitrary HWND.

| Pipe | Recorder to collector | Collector to Recorder |
| --- | --- | --- |
| Control | Bind and configure, prepare/revoke a visit grant, activate an admission epoch, renew the lease, environment revisions, Stop | Ready with registration, exact grant acknowledgement, invalidation and lower QPC bound, health/failure, closed prefix and Stopped |
| Input | None after role binding | Existing typed raw/hook/HID, device, registration loss, per-producer sequence/QPC/gap/progress evidence, each associated with its source generation and granted interval when scoped |
| Context | Bounded focus and pointer queries, typed IME focus/key requests, held-state resync, cancellation and clipboard fence requests tied to a grant | Native observation deltas, UIA result and permitted commits, IME/held-state and clipboard fence results, and typed gap/progress evidence |

Stream configuration with one bounded approved entry at a time, enforcing the existing 64-executable, 4,096-byte identifier caps and exact declared count before sealing. The sealed profile contains canonical approval entry keys. Later grant preparation carries the exact Windows-reported image spelling for a live process instance as a typed observation, never a file-open instruction. The path spelling bridge is specified in section 4. Keep the existing 8,192-byte input payload limit and typed field counts. Cap each new control or context message at 64 KiB including its header, with existing platform caps for UIA strings, ancestor count and commit UTF-16/part count enforced independently. One item per notice/read/commit; large snapshots are deltas in the existing per-visit order, with end marker or explicit loss. An input lane starts with the ordinary mapping's 256 outbound slots, a context notification lane with the existing 1,024 notice slots, UIA and IME retain their existing pending caps, and each pipe direction has a fixed maximum of one outstanding overlapped read and write. Keep the existing native raw/hook queue capacities and the existing recorder journal and staging caps. Bound command queues (eight queued control commands, one current grant, at most one pending grant). Stop, revoke/failure and lease expiry cannot sit behind evidence or a `FlushFileBuffers` wait. Coalesce only existing replaceable environment/health snapshots and monotonic watermarks; never coalesce event/loss accounting away. Drain at most the existing per-poll batch budget, with control processed independently before collection/publication.

Preserve original native source QPC, source coarse tick, receipt QPC, producer ID and sequence. Both processes use the same system QPC and validate frequency before use. Capture progress is a strict exclusive bound: shift no bound forward until all earlier records in that producer and grant are delivered or represented by ordered loss/suppression. Safe foreground suppression is accounted as insufficient coverage or a closed grant, not as known key-up or hook failure. On data pressure drop newest, accumulate bounded count and first/last missing sequence/time outside the queue, send the gap before later retained data, and feed existing resync rules. If a mandatory revocation cannot be transmitted, stop and let the other side close from its last certified bound. A malformed record is a transport failure, not retryable evidence. Context or UIA provider unavailability follows existing typed per-read outcomes when the host itself remains healthy.

### 3.3 Liveness and cancellation

Use a one-flight launcher within the eligible medium-integrity Recorder outside the controller, UI and scoped capture joins because the shell call can block for consent. Close admission before the shell request. Stop or timeout immediately cancels the connection ticket and disables the pipe servers and any future grant. Windows may still show or finish an already dispatched consent dialog. The orphaned launcher owns only its guard/launch handles and hands back the result only while the ticket is live. If the shell later starts the image, it cannot authenticate or collect and it exits at its boot deadline. The session never waits for that shell call to return after cancellation. A process-wide one-flight latch remains occupied until the outstanding shell call actually returns, preventing prompt stacking between attempts.

Start the high supervisor and its absolute boot deadline before any trust inspection or worker/native setup that could block. After the parent handle is available, the high supervisor waits on the original parent process handle, overlapped control events/cancellation and an absolute startup/lease deadline. Active grants also have expiry. Use the existing five-second helper readiness budget for authenticated registration after the shell returns, with a separately bounded 60-second consent ticket. Use a 250 ms heartbeat, expiring after 1 s without a fresh renewal, and the ordinary 750 ms cleanup bound or a shorter propagated session-end/suspend deadline. These are implementation limits, not verified performance figures. Renewal carries current controller liveness and input-pump progression, the live session/epoch and an increasing lease sequence. An I/O thread cannot renew from stale snapshots. Opening a new grant requires current desktop/foreground proof independently of the session lease. Sleep, lock, desktop switch, expiry or QPC regressions latch revocation; resume needs an explicit fresh epoch, and a dead lease cannot be revived. The parent may receive process termination access from Windows but never depends on it or on putting the high child into the ordinary job.

The high supervisor runs separately from all COM, UI notification, hook and raw owners. It performs only bounded checks and I/O, with no provider/window messages or producer joins in its wait loop. An independent high gate witness observes desktop, lock, session, power and foreground changes; loss of the witness's progress also revokes. The supervisor revokes atomically on parent exit, lease/transport loss, Stop, or an unsafe state, interrupts outstanding I/O and wakes owners. Further target reads and egress see the revocation immediately. Attempt graceful unregister/release and drain only already certified pre-cut data when authorized; enforce a deadline even for a permanently blocked UIA/COM thread or stuck unregister. Register each provider call and subscription teardown against its grant and deadline before invoking it. On expiry/invalidation stop dispatching detailed calls, and if a revoked call/worker fails to join before the cleanup deadline, forcibly terminate this process from the supervisor with `TerminateProcess(GetCurrentProcess(), ...)`, bypassing DLL detach. The core does not wait beyond its own deadline and records the last certified prefix. Parent death, lease expiry and untrusted startup do not drain private data. Link no child-process launcher into the collector, so process termination bounds all privileged workers.

## 4. Target authorization and source transitions

### 4.1 Identity and readiness

Use the existing profile's exact canonical full executable-path identity. A process-name inventory is a discovery hint only. The initial process scan confirms that a positively identified approved process exists and preserves conservative unknown-candidate and coverage behavior. At the final countdown check and on live foreground transitions, classify the actual foreground as eligible for the standard source, a candidate for the separate collector, unapproved or unknown. Inspect token elevation, integrity, session and user relative to the Recorder's measured token. Apply the inherited high access or protected split-pair requirements before selecting the source. Use a limited-query process handle with its creation FILETIME and PID. Bind HWND and thread from Windows, then re-read foreground HWND/thread/PID after identity queries. Resolve executable aliases in the Recorder with the existing canonical resolver. Bind the independently observed Windows-reported image spelling and exact canonical match to the live instance and the immutable approval entry. The high process checks the actual image spelling, live process handle/creation, HWND, thread, foreground, same user, linked logon pair, Windows session and target integrity independently. It never opens a supplied target path. Collector authorization requires both core canonical matching and the collector’s independent proof, with no approval by basename, title, HWND or PID alone.

An elevated background process does not prompt or prevent ordinary recording. A positive approved foreground observation with a supported medium-to-high split pair is required to request UAC for the collector. An unreadable possible target is an explicit verification failure or an unapproved/unknown gate outcome. Neither process accepts an opaque target on trust. Recheck token facts on prepare and renewal. Process restart/PID reuse, incompatible integrity changes, original proof expiry, HWND/thread replacement or foreground/desktop notification loss invalidates the grant. Focus changes within the same foreground revoke the associated focus generation, pending text, and affected reads. Monitor/geometry changes invalidate observation bindings. Keep identity/liveness caches bounded and keyed by process instance. A same-name restart requires entirely new approval.

The core controller alone writes global admission, origin and epoch. The input/context pump implements one source selector with standard, transition closed and collector phases. An authenticated but inactive process is a resource, with no admission authority. Prepare and activate the source in this order.

1. The core independently resolves the actual foreground, clears its old frame approval and requests a closed boundary before preparing an elevated grant. A fresh grant ID binds the actual process/window, immutable profile entry, desktop and session lease. The high observer verifies station, thread and currently active desktop, and the target proof. Both must be on the same normal WinSta0/Default interactive desktop, unlocked and awake. Matching names alone are insufficient across different stations or sessions. Neither process attaches to a different desktop.
2. Armed is a grant-local phase while global admission is closed. It permits registration, exact foreground/focus proof and a held-state readiness probe only, bound to its own observed Arm QPC. Register both low-level hooks and all existing required Raw Input collections through the shared path. Verify readiness and the exact foreground/witness revision, then run the scoped held-state probe with the same pre/post checks as an active sample. Send typed Known/Unknown readiness and proof, registration and grant ID. Do not transmit the pre-open bits or use them as a seed. Revoked proof, missing required access, expiry or host failure blocks startup or resume. No regular input or context payload can escape while armed. Reestablish proof after UAC. If necessary, wait within readiness for the exact candidate to return to the foreground. A different instance cannot inherit the pending grant. Startup consent stays bound to the original foreground candidate. Once a configured collector is idle, each new live preparation independently selects and approves the actual foreground.
3. After Armed reaches a terminal readiness result with valid target/access proof, prior producers close and all pause reasons clear, the controller opens using the ordinary Start/Resume QPC sampling. Actual Start retains t=0 and is distinct from Arm QPC. Pass activation for exactly that epoch, grant, current lease and target. The high process rechecks proof and acks or fails. Neither side enables elevated evidence egress/publication or FramePolicy on ack alone. Keep those gates closed through the post-activation resync result. Drop every pre-activation, countdown, stale-grant or pre-UAC record.
4. After activation permits scoped reads, obtain the actual held-state snapshot from the same selected native source, while its publication gates remain closed. The high owner applies the existing high-bit physical modifier/button, Caps Lock and swap sampling. Check active desktop, live target/access/integrity, visit and activation before and after the bounded sample. Verify appropriate access on that same desktop (`DESKTOP_HOOKCONTROL` or `DESKTOP_JOURNALRECORD` for another process's foreground, per GetAsyncKeyState). If these checks fail, zero is unknown and cannot become a synthetic release. Use one outstanding held request with the existing bounded retry interval. Only the current request ID, grant and actual sample QPC at or above the opening/loss boundary are eligible for the existing matcher and synthetic edge algorithm. While opening or loss resync is unproven the eligible input prefix is held or classified as uncertified. Never use the old source to complete the new source's snapshot. On a fresh terminal result with the grant still current, establish frame/context eligibility and feed the held result to the existing input path. A typed Unknown within a still-valid authorized scope allows no edges or reconstructed held bits; report uncertified input and use the existing retry/matched-evidence rules. Unknown required authorization/access or fatal timeout keeps all outputs for that collector-backed visit closed and fails the attempt. The common lower bound for eligible results from the collector is at least actual Start/Resume, activation and sample cutoff; input stays strictly after accepted resync. The interval before this barrier is recorded as suppressed or uncertified, without moving media PTS. Win32 sampling is a small sequential read, with a measured interval, and does not imply an atomic snapshot of hardware.
5. High capture and egress independently refuse a nonmatching or torn proof. Upon a change, revoke the old grant before enabling reads or egress for the new foreground, invalidate outstanding results and wake core through control. Retain a trusted WinEvent time's uncertainty and use the conservative lower endpoint for privileged input/context. If the witnesses disagree, close from the last certified prefix. Clear core frame approval before accepting evidence for the proposed grant. Suppress old evidence outside the certified pre-cut prefix. A late ack, old focus proof or delivery watermark cannot establish a grant. Environmental/foreground evidence affects its own reason and cannot remove another reason.

### 4.2 Admission ownership and transitions

| Condition | Controller and Recorder | Elevated collector |
| --- | --- | --- |
| Approved foreground eligible for standard access at countdown end | Use existing startup, input, UIA and resync, including when access is already inherited | Absent |
| Approved candidate requiring the collector at countdown end | Show collector consent and readiness status. Keep startup unadmitted before and through the shell/UAC request. Wait for matching approval and readiness | Authenticate, prepare, wait for exact activation |
| Active standard source → approved target requiring the collector | Clear frame approval immediately on detection and latch the source change against the old epoch. A rapid return to a foreground eligible for the standard source cannot reopen that epoch while Pause is pending. Close the old epoch and finish its published prefix. Request UAC once only after global closure and only if no authenticated high process is already attached | Prepare the exact approved foreground. Gate input, context and resync until activation |
| Active collector → approved target eligible for the standard source | Revoke high grant, close old epoch and finish the certified prefix. Reopen the attached standard source with a fresh epoch and ordinary resync | Cancel target work; unregister active producers and subscriptions. Clean process stays capture-closed under current session lease for possible reuse |
| Active collector → different approved foreground requiring the collector | Close old grant and epoch. Reauthorize the actual replacement and reopen after readiness. Focus-only changes within the same grant revoke focus-specific work | Refuse evidence from the old or unapproved visit and prepare the new grant independently |
| Unapproved or unknown foreground, lock, secure desktop, suspend, manual pause or low disk | The standard source keeps existing suppression and environmental behavior. The collector path closes the associated grant and waits for a fresh valid foreground and independent pause reasons to clear | Revoke. No target-facing reads, egress or resync while closed. In environmental closure a healthy idle process can wait under the lease |
| Decline, unsupported elevation, required readiness failure, timeout, stuck owner or peer fault | Before Start, fail startup without an admitted recording. After Start, stop and finalize only the provable prefix as a failed attempt with diagnostics and a visible reason | Cancel and exit under bounded independent cleanup. No automatic restart |

After the controller has closed admission for UAC, no producer may begin capture or commit evidence with a receipt at or after that cutoff. Earlier eligible prefix work may drain under its existing budget, with retention bounded by the certified grant. An independent pause retires the old authorization and cancels an undispatched launch request. Stop, session-end and app exit cancel the launch ticket. If the user presses Stop before admission it is cancellation; after admission it follows existing Stop and a late consent response cannot change that outcome. Consent failure has no automatic retry. Use actionable English UI status/error text for approval declined, unsupported account/logon, untrusted deployment, target moved, timeout and host failure. The UI reports status. Collector secrets, target handles and authorization remain with the capture owners.

Standard source → collector → standard source stays on the same QPC origin, attempt ID, media PTS, stream counters and controller timeline. Controller boundary time applies to all producers. Internally combine it with the earlier conservative evidence cutoff, using only records strictly in the certified prefix. Represent the uncovered difference as suppressed/uncertified coverage. Use existing pause/discontinuity/blind and paused-slot reporting with typed elevation-transition and source-failure reasons. The existing frame and still gates suppress uncertain/staged frames and invalidate prior approval generations. External Windows detection may arrive after an earlier frame was persisted. M1 retains that documented restriction; M3 retrospective hold/cut remains deferred. UAC dispatch itself is ordered after closure, including when Windows puts its prompt on the normal desktop.

Keep the original ordinary helper attached under its job. Drain and discard inactive ordinary input so its deliveries and losses do not enter high health, matching or held state. When high is inactive its privileged producers and subscriptions are unregistered with no target reads or egress. A missed cleanup deadline is privileged-source failure. Stop destroys both paths. Translate device IDs at ingress through a bounded inventory keyed by source instance and native device lifetime. Existing calibration identity can use a validated path hash and descriptor, and must never alias raw handles or held state across owners. Track missing or overflowing inventory without fabricating identity.

Use existing `Receiver::interrupt`/pause/flush for the old source and `Receiver::reopen` for the new source in both directions. Close already published downs with existing synthetic boundary releases. Invalidate old physical state and matching/sampling/controls, pending focus/pointer/IME/UIA/commit, motion-rest, provisional stills and hook-health streaks. Preserve durable prefix counters and real loss evidence. The new source has its own sequence/progress namespace and required registrations and gets a fresh resync. Do not let intentionally suppressed samples resemble device unplug, hook loss or a hotkey release.

## 5. Observation and publication algorithms

### 5.1 Privileged producer gate

Use a dedicated high environment/foreground witness based on the current WinEvent and WTS/power owners, plus a bounded refresh independent of detailed context, IPC writers and COM. It observes exact foreground/desktop changes, thread/window destruction, loss of notice continuity and monitor/environment revisions. It has a local monotonic revision, latest positive proof and conservative cutoff per grant. It publishes only this bounded state to the gate. Lock, sleep, desktop switches, notice loss, witness stall and failed attestation revoke rather than continuing on cached positive state. A gate is live only with a current parent lease and fresh witness. Delayed WinEvent source time constrains the admissible prefix; later arrival does not change the source time.

Reuse the current local receipt stamp and foreground protocol for Raw Input. On elevated low-level callbacks, capture the native QPC/source tick and a cheap foreground HWND/thread/PID tuple, with grant/witness generation checked before and after the copy. Keep the existing pass-through hook semantics and constant, bounded callback work. Perform no process opening, token queries, UIA, pipe I/O, filesystem access or waits in a callback. Verify the queued cheap tuple against the pinned process proof on the non-callback collector owner. For any producer require unchanged authorization on entry to detailed reads, on their return and at egress. Reject a changed desktop, different foreground, stale/missing proof or doubtful source time (including a queued source that can belong to the prior interval); never reassign doubtful input to the new foreground. Maintain native device/gap/progress semantics within a certified interval. For pre-activation, invalidated or out-of-scope observations, drop payload at the gate and represent only loss of coverage, without per-key event counts from an unapproved target. Use immutable copies/checks and bounded drop-newest queues; no callback writes a pipe.

A foreground check and later Windows API work cannot be one transaction. A native focus/geometry or WinEvent snapshot, notification already queued, low-level callback, `GetAsyncKeyState` batch, UIA lookup/cache read/ancestor or subscription call, existing IME `SendMessageTimeout` and a pending overlapped pipe write can complete after external change or revocation. Each completion retains the old request/grant and proof interval, and is discarded on mismatch, stale scope or newer revision. Bound provider teardown independently as in section 3.3. For a WinEvent ABA return, use the revision/uncertainty instead of treating equality of the final HWND as evidence that no intervening transition happened. If a boundary may overlap an item, discard it from the privileged prefix. A request already dispatched to Windows cannot be cancelled atomically by a new foreground observation. A consumer does not rely on revocation message arriving before an already in-flight data record: it checks its own live witness, known cutoff, expected revisions, expiry and relevant certified coverage before admitting. An authorization loss cannot make queued records eligible again.

### 5.2 Privileged and ordinary observations

Retain the core `Context` owner for focus-generation allocation, current/historical visits, scope and journal rules, timing, geometry, monitor mapping, cursor, app-busy/hung decisions, clipboard and save evidence. Separate the Windows mechanics that can require target-level access from these decisions. Keep the current local workers for ordinary focus/point targets. Translate currently native `Visit`, `Query` and `Read` into bounded protocol evidence, request IDs, original QPC fields and explicit outcomes. Retain current UIA timing and property/ancestor limits, and existing IME request/message/timeout semantics. Correlate one current Focus and one current Pointer request and the existing IME/commit capacities. Stale completions never replace current results or acquire a new timestamp.

For Focus, re-read the actual native focus within the expected foreground incarnation and validate its typed focus snapshot before/after provider work. For Pointer, use the existing physical-point hit and root-window checks on both sides. When the hit is another approved window requiring the collector while a grant is active, establish an exact independently approved point-window proof bound to that one request and the active foreground. Forward actual unavailable status as in the ordinary path. No caller chooses a native message, property list, COM method, target process or HWND for an unrestricted read.

Retain the same ancestor bounds, subscription behavior and text-edit commit checks. ## 6. Remediation amendments and clarifications (2026-11-17)

These follow the M1 remediation plan and the user decisions D-8 and D-9 of 2026-11-17. Where they differ from the sections above, they apply.

### 6.1 Wire payloads

- Each message is one fixed binary header followed by a payload. The payload is a schema-checked serde encoding of one specific bounded Rust type, decoded with the checks of section 3.2.
- "No JSON rows" in section 3.2 refers to journal rows: no journal row, or any other output-format record, crosses the wire.
- Any change to a type in `protocol/src/ipc/elevated` requires an increment of `attachment::VERSION`, so that peers built from different revisions fail the version binding instead of misreading a payload.

### 6.2 Readiness budget

Each preparation (startup or resume) gets its own 5-second readiness budget from the moment the shell returns, inside the separately bounded 60-second consent ticket. A new preparation does not inherit the remainder of an earlier one.

### 6.3 Provider deadlines

- Each collector read carries the Recorder's request deadline: at most 500 ms for UIA and at most 50 ms for IME. The provider's own Windows timeouts are set to the remaining budget: the UIA transaction timeout per call, and the `SendMessageTimeoutW` timeout for IME.
- The supervisor's slot deadline for the call is the request deadline plus the 750 ms cleanup bound.
- At the request deadline a call still running gets the typed `TimedOut` result for its request. The grant stays valid, and no new call is dispatched to that provider kind until the running call returns. This is a recorded loss (G).
- A call that returns between the request deadline and the slot deadline is discarded as stale; its provider kind becomes available again.
- A call still running at the slot deadline has defeated cancellation. The supervisor revokes and terminates the collector (section 3.3), which is an admitted source failure and fails the attempt.

### 6.4 Target changes and ineligible foregrounds (D-8 A)

- A foreground or focus change while a grant is Preparing, Armed, Activating, awaiting its held result or refreshing is a transition, not a fault: the grant is revoked.
- Before admission the selector prepares again for the original candidate while the readiness budget remains. If the budget expires, startup fails without an admitted recording.
- After admission the epoch stays closed with `ElevationTransition`, and the actual new foreground is classified fresh.
- An approved foreground whose token is not eligible (different user, different session, protected, or failed linked pair) is suppressed with reason `ineligible_token`, like an unapproved foreground, including the suppression accounting of the M1 specification addendum A6.2.
- Only host, transport, authentication and protocol failures, lease loss, witness regression, readiness-deadline expiry and failure of required access on the current grant fail the attempt.

### 6.5 Collector-side approval proof (D-9 A)

- On prepare the collector independently resolves the image of the pinned live target process: it takes the path from the live process handle, opens the file without write or delete sharing, reads its final path by handle and its file ID, and canonicalizes with the same function as the Recorder's resolver.
- The grant requires equality with the sealed approval key. Any failure is a target-access failure before admission.
- This work runs only on the collector's owner thread, never in callbacks, and never opens a path supplied by the Recorder.
